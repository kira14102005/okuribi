## 0. Non-negotiable safety rule (design this in from day one)

The "cursed repo" is **entirely generated by your game**, never a path the player points you at.

```
okuribi/
  world/
    cursed_repo/        ← a git repo YOUR setup script creates
    cursed_repo_origin/ ← a second local bare repo acting as "the remote"
```

- `scripts/setup_cursed_repo.py` creates both from scratch with a handful of fake commits (lore files, not real code).
- The game's filesystem/git tools are **hard-coded** to operate only inside `world/cursed_repo/` — path-check it in code, not just by convention, so even a bug can't reach outside the repo root.
- No real GitHub token, no real remote, no `--force` against anything the player owns. "Force-pushed to origin" is a push to your local bare repo, rendered in the UI to *look* like a remote push.

This is the whole trick: all the dread, none of the blast radius.

## 2. Major components — what and how

### 2.1 World bible (`world/truth.json`, `world/npcs.json`)
**What:** ground truth — who the real dead student is, which documents are forged, what each NPC knows/hides, the clue list mapping document/NPC IDs → clue IDs.
**How:** hand-authored JSON/YAML, no LLM involved. This is your most important file — build it before any code.

### 2.2 Archive corpus + retrieval
**What:** ~25 documents (diaries, clippings, logs) with metadata: `date`, `author`, `type`, `reliability`, `forged: bool`.
**How:**
- `scripts/generate_docs.py` — batch-prompts E4B offline to draft documents from the truth file, you hand-edit for consistency.
- `scripts/build_index.py` — embeds and stores in Chroma with metadata filters.
- A plain Python function `search_documents(query, filters) -> [doc]`, no LLM in the retrieval path itself.

### 2.3 MCP servers
**What:** two small FastMCP servers.
- `mcp_servers/archive_server.py` — `search_archive`, `get_document`, `cross_check(doc_id_a, doc_id_b)`.
- `mcp_servers/cursed_repo_server.py` — the Option B mechanic:
  - `get_repo_status()` — current commit count, "corruption level"
  - `corrupt_step()` — called on each wrong move: rewrites a commit message, deletes a fake file, or force-resets a branch *inside `cursed_repo/` only*
  - `seal_fate()` — called on a full loss: writes `DEAD.md`, commits it, and does a `git push --force` to `cursed_repo_origin` (your local bare repo)
  - `restore_repo()` — called on a win: resets `cursed_repo` back to its initial commit
**How:** every function opens the repo with an absolute, hard-coded path under `world/cursed_repo`; reject anything else even if somehow passed in.

### 2.4 Director graph (`game/graph.py`)
**What:** the state machine from the earlier plan (router → action nodes → clue_check → narrator → AP tick → ritual/loss check).
**How:** LangGraph `StateGraph` over a Pydantic `GameState` (AP, loop_number, notebook, clues_found, corruption_level, phase). Each wrong/costly action also calls `corrupt_step()` via the cursed_repo tool, so git degradation is visibly tied to your mistakes.

### 2.5 NPC subgraphs
**What:** 3–4 suspects, each a subgraph with its own Store namespace (what they've revealed this loop) and an "allowed facts" list so E4B can't invent lore.
**How:** one subgraph template parameterized by NPC id + persona + allowed_facts; instantiate per NPC.

### 2.6 Ritual + loop control
**What:** `interrupt()` pauses for the player to name the dead student + offering; a pure-code `verdict()` checks against `truth.json`.
**How:** correct → ending node + `restore_repo()`. Incorrect → death scene + `corrupt_step()` (bigger hit than a normal wrong move) + loop reset via a new thread id, notebook carried over through the Store.

### 2.7 LLM layer (`game/llm.py`)
**What:** one `ChatOllama` wrapper, E2B for routing/classification, E4B for narration/dialogue, Pydantic-validated structured output with a repair/retry node on failure.
**How:** `num_ctx=4096–8192`, `num_predict≈100`, stream to UI, `OLLAMA_MAX_LOADED_MODELS=1`.

### 2.8 UI (`app/ui.py`)
**What:** Streamlit — chat pane, AP counter, notebook sidebar, and a **"corruption" panel**: a live-ish view of the cursed repo (commit count ticking down, log messages mutating, a creepy diff) so the stakes are visible, not just narrated.
**How:** poll `get_repo_status()` each turn and render it; this is the piece that sells Option B as "real" without being real.

### 2.9 Polish
**What:** README with a big **"this never touches files outside `world/cursed_repo`"** callout, demo recording showing a full loss (so judges see the `DEAD.md` force-push happen safely), optional Kokoro voice lines, the post.
