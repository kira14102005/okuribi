## 1. How Okuribi works

**Setting:** Hanamori High. The legend says that when the "Seventh Name" is spoken, a student dies. It stops only when the one who *actually* died is sent back through the Okuribi ritual. The twist is that everyone's memory of that student has been rewritten, so the school archive itself is unreliable.

**What you do as the player (a transfer student):**

1. **Investigate.** You have a limited number of **Action Points (AP)** per loop (say 8). Each action costs 1 AP:
   - Search the archive (diaries, newspaper clippings, club logs, enrolment records).
   - Talk to an NPC (3–4 suspects).
   - Cross-check two documents (a deterministic date/consistency check).
2. **The Calling.** When AP runs out, the curse fires and a student dies.
3. **The Ritual.** At any point you can spend your remaining AP on the ritual: name who you think the true dead student is and choose an offering.
   - **Right:** the true ending plays and the spirit is sent back.
   - **Wrong:** someone dies and the **loop resets**.
4. **The loop resets** with your notebook of clues intact. NPCs forget most of what happened, but a few leave a faint déjà-vu trace.

**One loop as a flow:**

```
START LOOP (AP=8) ──► player input
        │
   intent_router (rules first, E2B fallback → structured JSON)
        │
 ┌──────┼───────────┬──────────────┬─────────────┐
 ▼      ▼           ▼              ▼             ▼
archive  npc_dialogue  cross_check   notebook    ritual
search   (E4B, short)  (pure code)   view        (interrupt → choose name+offering)
 │         │              │                          │
 └────► clue_check (pure code: which clue IDs did this reveal?)
                │                                    verdict (pure code vs truth.json)
          narrator (E4B, ≤100 tokens)                 │
                │                          correct → ending │ wrong → death + loop_reset
          AP -= 1 → AP==0? → The Calling → loop_reset
```

**What makes it work on a small model:**
- The truth lives in a hand-written `world/truth.json` (who the ghost is, which documents are forged, what each NPC knows or hides).
- Clue discovery is **deterministic**. If you retrieved document `D14` or an NPC said fact `F3`, the clue is unlocked. The LLM never decides whether you found a clue.
- The LLM writes only dialogue and short narration, constrained by the facts each NPC is allowed to reveal.

## 2. Major components

| # | Component | Tech | Role | Risk |
|---|---|---|---|---|
| 1 | **World bible** | JSON + markdown | Truth, NPCs, rules, document list, anime logline | Low (but the most important) |
| 2 | **Archive corpus** | ~25 generated, hand-edited docs with metadata (date, author, type, reliability, forged flag) | The conflicting-sources RAG material | Medium |
| 3 | **Retrieval layer** | Chroma/FAISS + `nomic-embed-text` via Ollama | Search plus provenance labels | Low |
| 4 | **MCP servers** | `archive-server` (search, get doc) and `timeline-server` (events, date checks) | Your first custom MCP tools | Medium |
| 5 | **Director graph** | LangGraph (StateGraph, conditional edges, SQLite checkpointer) | Core game loop | Medium |
| 6 | **NPC subgraphs** | LangGraph subgraphs + Store namespaces | Per-NPC persona, memory, knowledge limits | Medium–high |
| 7 | **Memory** | Checkpointer (per loop) + Store (cross-loop notebook, déjà-vu traces) | Short-term vs long-term memory | Medium |
| 8 | **Ritual and loop control** | `interrupt()` + `Command(resume=...)`, checkpoint/fork | Human-in-the-loop and time-travel | Medium |
| 9 | **LLM layer** | Ollama, E2B (routing), E4B (dialogue), Pydantic structured output + retry node | Robust small-model usage | Medium |
| 10 | **UI** | Streamlit or Gradio, streaming text | Chat, notebook panel, AP counter | Low |
| 11 | **Polish** | Pre-rendered Kokoro voice lines, README, demo video, post | Presentation | Low |

Check the current docs for `langchain-mcp-adapters` and the MCP Python SDK before you start. MCP changed recently, so confirm the transport and version they target.
